# Agent 工作时的进度：任务状态、按事件的语音汇报、对话归属（2026-09-29）

## 用户的要求和判断

- Agent 执行任务时，对自己步骤的报告要更详细，让用户随时知道发生了什么；普通情况下频率可以低一些。
- 写代码、后台操作时，现在的界面体现不出它在做什么，要设计。
- 讨论后确定的方向（用户同意）：
  - 屏幕详细、连续，语音稀疏，只报里程碑；
  - 按事件汇报，不按时间汇报；
  - 按用户是否在看来调节；
  - 交给语音的是按时态分好的事实。
  - 实施顺序：服务端任务状态 → 语音 → 任务卡界面 → 离开 App 后的进度 → 验收。

## 调查：之前的问题（甜甜圈那一轮，对话 01a0ebad）

- **按时间汇报**：每 20、30、45 秒说一句“还在处理中，抱歉久等”，没有信息；有进展时又因为两次之间至少隔 6 秒而漏掉。
- **信息源差**：语音只拿到 `blender -b -t 6 --python make_donut.py` 这样的命令行，说不出具体内容。
- **把计划说成事实**：Codex 说“我会做……完成后附在回复里”，语音说成“现在已经开始渲染了”。

## 数据源（Codex 0.156.1，`codex app-server generate-json-schema` 实际核对）

| 事件 | 用途 | 状态 |
|---|---|---|
| `turn/plan/updated` | 计划清单，步骤状态为 pending、inProgress、completed | 已用 |
| `item/started`、`item/completed` | 命令（带 Codex 自己的解析 `commandActions`：read、listFiles、search）、文件改动、MCP 调用、网页搜索、看图、生成图片 | 已用 |
| `item/commandExecution/outputDelta` | 运行中命令的输出：最后一行和进度 | 已用 |
| `item/fileChange/patchUpdated` | 正在写的文件、增删行数 | 已用 |
| `item/reasoning/summaryTextDelta` | 推理摘要（英文居多） | 未用 |
| `turn/diff/updated` | 整个回合的 diff | 未用，留给任务卡查看改动 |
| `item/mcpToolCall/progress` | 工具调用中途的进度 | 未用；助理屏的字幕走 `rungic_cua.activity`（docs/88） |

- **计划工具默认关闭**：`update_plan` 要在配置里开启。Codex 源码 `core/src/config/mod.rs` 的 `resolve_update_plan_enabled` 只读 `tools.update_plan.enabled`（b412ff3）。
- **实测**：没开启时，Agent 在它的工具列表 `ALL_TOOLS` 里搜 `update_plan`，只找到桌面工具。现在创建和恢复对话时，都传 `config: {"tools.update_plan.enabled": true}`。
- **Codex 会自己转述旁白**：Codex 把 agentMessage 旁白以 `[BACKEND]` 消息交给实时语音，所以服务不再另外转述“打算”；最初实现里转述过一次，结果同一句话说了两遍。

## 实现

- **`plasma/voice-agent/task_state.py`**（安装到 `/usr/lib/rungic-voice-agent/`）：每个回合一个 `TurnState`。
  - **命令转成人话**：先用 `commandActions`（读取 x.py、查看某目录里的文件、搜索“…”）；否则按程序归类，例如“在后台运行 Blender（make_donut.py）”“运行 Python 脚本 render.py”“安装或查询软件包”“Git status”。
  - **输出**：去掉终端控制字符，按回车和换行取最后一行。进度只认明确的形式：百分比，或 “Sample/Tile/Frame/Step… x/y”。
  - **文件**：新建、修改或删除，以及增删行数，在整个回合里累计。
  - **推理**：推理不算一步。原来的“想下一步”每隔几秒就开一次关一次，界面和语音都在闪。
  - **`snapshot()`** 给任务卡：计划、当前一步（文字、明细、进度、秒数）、最近完成的步骤、改动的文件、旁白。
  - **`facts()`** 给语音，按时态分行：已完成、进行中、还没开始、此刻正在（秒数、百分比）、接下来打算（注明还没做完）。
- **服务**（`rungic_voice_agent.py`）：
  - 接入上面的事件，经过合并，每秒最多约 2.5 次向 App 发 `{"type": "task", …}`（不写入记录）。
  - 回合结束时写入一条 `final` 的任务记录，保留计划、步骤和文件。
- **语音**（`progress_reason`）：
  1. 计划至少两步时，报一次计划；
  2. 进入计划的下一步时，报一句；
  3. 单步超过 40 秒，报一次进展（有百分比就说）；没人看的情况下，间隔 45 秒可再报一次，有人看时间隔 90 秒，每一步最多报两次；
  4. 没有计划时，一个新的步骤持续 4 秒以上就报一句（有人看时，至少隔 30 秒）；
  5. 开始 25 秒后仍一句没说过，就说一次“还在处理”。
  - **汇报间隔**：两次汇报之间，没人看时至少隔 8 秒，有人看时至少隔 20 秒。
  - **致歉**：用时超过 90 秒，只道歉一次。
  - **说话的约束**：进度消息开头注明“系统给你的进度信息，不是用户说的话”，并要求只说列出的事实、分清时态。实测曾有一次语音回了“我听到你接下来的进度了”，这条注明就是针对这种情况。
- **是否在看**（`SetWatching`）：
  - App 窗口处于激活状态时，或浮层显示时，客户端上报“在看”。服务按 D-Bus 发送者分别记录，客户端离开总线时清除。
  - 手机本身还要在显示 Plasma：平台桥 `status` 的 `foreground`，熄屏或回到 Android 桌面时为 false，结果缓存 3 秒。
  - 服务重启后，App 会重新上报。
- **提示词**：
  - `agent.md` 要求多步任务一开始就用 `update_plan` 列 2 到 6 步中文计划，并随进度更新；旁白写“接下来打算……”。
  - `realtime.md` 说明进度事实按时态划分，不能把打算说成已做。

## 实测（实机）

- **写统计脚本的任务**（新对话 01a0ec39，为了不打扰用户，测试时关掉了“朗读回答”，结束后恢复）：
  - 计划：确认图片文件夹 → 写统计脚本 → 运行并核对结果。
  - 三步的状态依次更新，回合结束时的清单写进了记录。
  - 语音只收到一次我们的进度：报计划，事实的时态都正确。其余由 Codex 的旁白转述。
- **Blender 茶杯**（新对话，手机锁屏）：
  - Agent 按新提示词用 `desktop_launch` 在助理屏上开 Blender，但 `rungic-agent-screen on` 超时，于是退回后台渲染。
  - 锁屏、熄屏时助理屏起不来，原因尚未查明。
- 单元测试：`tools/test_task_state.py`，5 项。

## 顺带修复：按住说话进了别的对话（用户报告）

- **现象**：App 退到后台或切到别的应用，再回来按住说话，当前对话里没有气泡，也看不到回复。
- **机制**：
  - 服务同一时间只打开一个对话，按住说话、发文字、朗读都作用在打开的那个上面。
  - App 页面只显示自己对话的事件。
  - 其他客户端打开别的对话后，App 的下一次说话就进了那个对话，而页面把它的事件都过滤掉了。
- **会造成这种情况的路径**：
  - 长按 Home 用浮层说话：`AssistantTalk` 打开“语音助手”对话；
  - 服务重启后，浮层也收到 `agent-restarted` 并重新打开自己的对话（本轮前半段引入）；
  - 服务预热：没有打开的对话时，自动打开“语音助手”对话。
- **实例**：16:04:35 用户一句“API Key 存在哪”进了“语音助手”对话，语音回答播放了，但屏幕上没有显示。
- **修复**：
  - 服务新增 `Use(conversation)`：确保打开的是这个对话，打开后才返回。实测从别的对话切回来只用 0.04 秒，恢复在后台进行。
  - `AgentClient.conversation` 由页面绑定，浮层也绑定自己的对话。按住说话、免提、发文字、朗读之前，都先 `Use`，等返回再执行。
  - 服务每个 D-Bus 调用在各自的线程里运行，所以期间到来的松手、取消、停止、转文字都排在后面，按顺序执行。
  - 浮层收到 `agent-restarted` 时，只有正在显示才重新打开自己的对话；否则等下次呼出时再打开。
- **同批修复**：`Main.qml` 缺少 `import com.rungic.voiceassistant`，`Component.onCompleted` 报 ReferenceError，`--conversation` 启动时不会打开对话（本轮引入，已修）。
- **待验收**：UI 路径“浮层接管后回到 App 按住说话”需要真人操作。测试时手机锁着，只验证了服务端的 `Use`。
