# 指针手势与移动算法：直接触摸、触控板、电视

2026-09-25。用户要求：
- 触控板上，指针移动的距离应该和手指移动的距离一样。
- 助理屏全屏和“手机当电视触控板”要用同一套算法，并从人因角度找出最佳做法。
- 所有手势（单击、双指右键、长按、拖动等）按最佳实践统一重构，做好抽象复用。

## 原算法的问题（APK 1.39 及以前，CastControls 沿用）

`gain = 1.3 + min(0.9 × 手指速度[手机像素/ms], 2.7)`，输入是手机像素，输出是目标屏像素。按本机 392 dpi（15.4 px/mm）换算：

| 手指速度 | 全屏时指针距离 ÷ 手指距离 |
|---|---|
| 10 mm/s | 1.4 |
| 50 mm/s | 2.0 |
| 100 mm/s | 2.7 |
| ≥195 mm/s | 4.0 |

主要有三个问题：
1. 单位没有按物理尺寸归一化，比例随手机像素密度和目标屏像素大小变化。同一套代码在全屏和电视上的实际比例完全不同：电视上手指移动 1 mm，指针走 20–62 mm。
2. 最低 gain 是 1.3，普通速度就已经在加速。
3. 速度用处理事件时的时刻计算，也没有用 Android 合批的历史采样，所以噪声很大。

## 依据

- 控制-显示增益（CD gain）：gain 过低需要频繁抬手重来（clutching），过高会出现像素跳跃、精确定位变难。按速度加速的传递函数在大距离移动上优于固定增益（Casiez 等，2008）。操作系统都在物理单位（mm、mm/s）上定义曲线。
- **libinput 1.32.0**（`.work/cache/research/libinput`，提交 `5cf833b`，MIT），逐项核对源码：
  - 触控板加速（`filter-touchpad.c`，`touchpad_accel_profile_linear`）：
    - 低于 7 mm/s：因子为 0.1·v + 0.3，最低 0.33 倍，用于亚像素级精确定位。
    - 7–130 mm/s：恒定 0.9，是平台区。
    - 高于 130 mm/s：0.0025·(v/130)·(v−130) + 0.9，到 520 mm/s 封顶。
    - 最后乘 `TP_MAGIC_SLOWDOWN` 0.2968，并换算到 1000 dpi。所以平台区相当于约 **10.5 逻辑像素/毫米**。
  - 速度：由最近若干采样的时间戳计算，方向改变时截断；速度变化时用 Simpson 公式对因子取平均。
  - 轻点（`evdev-mt-touchpad-tap.c`）：
    - 轻点超时 180 ms，移动阈值 1.3 mm。
    - 轻点后 160 ms 内再次触摸（每多一根手指加 20 ms），进入“拖动或双击”状态；抬起得快是双击，移动或按住超过轻点超时就是拖动。
    - 一指、二指、三指轻点分别对应左键、右键、中键（lrm）。
- **统一的单位：视角。** 人看到的是指针的角位移。
  - 手机全屏时，画面就在手指下，观看距离也相同，所以视角 1:1 就是物理 1:1。
  - 电视：1920 像素宽，占视野约 35°，手指在眼前约 30 cm。视角 1:1 相当于 1920/35 × 0.191 ≈ **10.5 像素/毫米**，恰好与 libinput 的平台区相同，两个独立推算互相印证。横跨电视约需 1.2 个手机宽度的滑动。

## 新实现（APK 1.40，`plasma/native-apk/src/dev/moto/plasma/`）

| 组件 | 职责 |
|---|---|
| `PointerOutput` | 指针进入第二输出的唯一出口（castPointer：绝对移动、相对移动、按键、滚动、停止滚动）；点击时抬起延后 40 ms |
| `PointerTransfer` | 移动算法：输入按手机 dpi 换算成毫米，用采样自带的时间戳（含历史采样）计算 60 ms 窗口内的速度，按 libinput 曲线（平台区归一为 1）加 Simpson 平均；输出 = 毫米 × 目标屏“每毫米像素”。全屏时这个值是画面在手机上的像素/毫米（物理 1:1），电视为 `TOUCHPAD_TV_PX_PER_MM` = 10.5 |
| `GestureRules` | 共用阈值（180 ms、160 ms、1.3 mm）、按手指数选键、指尖中心点计算 |
| `TouchpadGestures` | 触控板：libinput 的轻点状态机（IDLE / TOUCH / TAPPED / DRAG_OR_DOUBLETAP / DRAGGING） |
| `DirectGestures` | 直接触摸：触屏上模拟鼠标的通行约定 |

使用方：`CastControls`（手机当电视触控板）、`AgentFullscreen`（全屏的两种模式）。原先写在这两处的手势代码已删除。

### 手势表

| 手势 | 触控板模式（全屏 / 电视） | 直接触摸模式（全屏） |
|---|---|---|
| 单指移动 | 相对移动指针，慢速时 1:1，快速甩动时加速 | 按下后移动 = 左键拖动，从按下点开始 |
| 轻点 | 左键（按下后等 160 ms，看是否还有第二次触摸） | 在手指处点左键 |
| 连续轻点两下 | 双击 | 双击（两次点击） |
| 轻点后再按住并移动（或按住超过 180 ms） | 左键拖动，抬起即结束 | — |
| 长按（400 ms，没有移动） | 无（触控板惯例没有长按） | 右键 |
| 双指轻点 | 右键 | 右键（落在两指中间） |
| 三指轻点 | 中键 | 中键 |
| 双指移动 | 滚动，内容 1:1 跟随手指，抬起后惯性滚动 | 同左 |
| 从横屏底部条带上滑 | 调出工具栏 | 同左；在条带内轻点、长按照常传给画面 |

移动阈值统一为 1.3 mm（本机约 20 px）。底部条带的触摸先暂缓转发：主要向上移动超过 20 dp 时算作调出工具栏；其他方向交给手势，从起点开始处理。这样上滑调工具栏时，不会先在画面上误拖一下。

## 实机测量（2026-09-25，全屏触控板模式）

CAST-1 当时的缩放是 1.75，全屏画面缩放为 1，所以 1 个手机像素等于 1 个输出像素。

| 滑动 | 速度 | 指针距离 ÷ 手指距离 |
|---|---|---|
| 300 px / 2400 ms | 8 mm/s | 0.99 |
| 300 px / 780 ms | 25 mm/s | 0.99 |
| 200 px / 100 ms | 130 mm/s（阈值） | 1.00 |
| 200 px / 40 ms | 324 mm/s | 1.79 |

直接触摸模式：
- 轻点任务栏启动器，菜单能打开和关闭。
- 在 Dolphin 文件区长按，弹出完整的右键菜单。Plasma Mobile 的面板和桌面本身没有右键菜单，那里没有反应是正常的。
- 指针落点与换算结果一致（按 1.75 缩放核对）。
