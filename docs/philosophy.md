# Agent OS：共同工作 / Working together

[中文](#中文) · [English](#english)

## 中文

我越来越觉得，做自己的 OS 是一件特别有意思的事。

因为 Agent OS 真正值得探索的地方，并不是「怎么让 AI 替我们把电脑操作掉」，而是：

**当 Agent 成为一种长期存在的工作主体之后，人和电脑之间的关系应该变成什么样？**

今天的操作系统，几乎全部是围绕人的操作能力设计的。

一个人面对一个桌面，在不同的 App、窗口、终端之间切换，把自己的注意力不断分配给不同任务。

所以我们今天使用 Agent 的方式，其实也还是继承了这套逻辑：

在一个终端里开几个 Agent，或者在一个 App 里管理几个 Agent。

看起来 Agent 变多了，但真正的中心仍然是「人怎么操作它们」。

而我想象中的 Agent OS，应该完全不一样。

它更像是一组长期存在的工作空间。

你可以有一个空间在做游戏原型，一个空间在研究音乐，一个空间在画画，一个空间在写某个项目。

每个空间里都有 Agent 持续工作，它们拥有自己的环境、上下文、工具和任务。

但这里最重要的一点，并不是「你把任务扔进去，然后等结果」。

我反而觉得，**人必须能够非常自然地参与到 Agent 的工作过程里。**

因为很多时候，真正有价值的东西并不只是最终那个文件、那段代码、那张图。

而是它为什么这么做，它遇到了什么问题，它尝试了哪些路径，它知道了哪些你原本不知道的东西。

如果我们只是把事情完全交给 Agent，最后拿一个结果回来，人自己其实没有成长。

久而久之，Agent 越来越强，但你和它之间的知识差距也会越来越大。

所以我更希望 Agent OS 是一种「共同工作」的系统。

Agent 可以承担大量探索、执行和重复劳动，但人可以随时进入它的工作空间，看到它正在做什么，接管其中某一步，和它讨论，修改方向，再把工作交还给它。

你不是一个站在外面发指令的人。

你仍然身处这个创造过程里面。

我觉得这可能也是 Agent OS 很重要的一层意义：

它不是为了把人从工作中彻底移除，而是让人从大量机械操作中解放出来，把注意力放到理解、判断、学习和创造本身。

而这也是为什么我觉得我们应该亲自参与 Agent OS 的构建。

因为现在这个形态远远没有被定义。

如果只是等待某个大公司最后把一个成熟产品交到我们手上，我们得到的仍然只是别人定义好的规则。

但如果现在参与进去，我们其实有机会一起回答一个更基础的问题：

**未来，人到底应该怎样和大量 Agent 一起工作？**

对我来说，这才是 Agent OS 最让人兴奋的地方。

## English

The more I think about it, the more interesting I find building an OS of our own.

The question that makes Agent OS worth exploring is not “How can AI operate the computer for us?” It is:

**Once agents become lasting participants in our work, what should the relationship between people and computers look like?**

Almost every operating system today is designed around what a person can operate.

One person sits in front of a desktop, switching between apps, windows and terminals, continually dividing their attention among different tasks.

The way we use agents today still follows that logic:

We run a few agents in a terminal, or manage a few agents inside an app.

There may be more agents, but the central question is still “How does a person operate them?”

The Agent OS I imagine should be very different.

It is more like a collection of persistent workspaces.

One workspace might be building a game prototype, another exploring music, another drawing, and another working on a project.

Agents keep working in each space, with their own environments, context, tools and tasks.

But the most important part is not “Drop in a task and wait for the result.”

I believe **people must be able to participate naturally in the agents’ work.**

Often, the most valuable thing is more than the final file, piece of code or picture.

It is why the agent approached the work that way, what problems it encountered, which paths it tried, and what it learned that you did not know before.

If we hand everything over to an agent and only collect the result, we do not grow through the work ourselves.

Over time, the agent becomes more capable, while the gap between what it knows and what we know keeps widening.

That is why I want Agent OS to be a system for working together.

Agents can take on much of the exploration, execution and repetitive work. People can enter their workspaces at any time, see what is happening, take over a step, discuss it, change direction, and hand the work back.

You are not standing outside, issuing instructions.

You are still part of the creative process.

I think this is an important part of what Agent OS can mean:

Its purpose is not to remove people from work entirely, but to free them from mechanical operations so they can focus on understanding, judgment, learning and creation.

This is also why I think we should take part in building Agent OS ourselves.

Its form is still far from defined.

If we simply wait for a large company to hand us a finished product, we will still be living by rules someone else has defined.

By participating now, we have a chance to answer a more fundamental question together:

**How should people work alongside large numbers of agents in the future?**

To me, that is the most exciting thing about Agent OS.
