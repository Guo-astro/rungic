# 长按 Home 呼出语音助手

> 改名说明（2026-09-26）：Rungic改名B阶段之后，容器内的`moto-*`包、程序、单元、路径，`MOTO_*`变量和`dev.moto.*`名称改为`rungic-*`、`RUNGIC_*`、`com.rungic.*`；Android侧的名称在C阶段（2026-09-27）改为APK `com.rungic.plasma`、`/data/adb/rungic-*`（镜像在`/data/adb/rungic-lxc/images/`）、容器中的`/var/lib/rungic-{host,cores,apt}`、`rungic-gpu-alloc`、`rungic-cast`、`debug.rungic.*`、dm `rungic-root`与SELinux `rungic_image`。对照与边界见[70篇](70-rungic-rebrand.md)。下文按时间记录的内容保留当时的名称。

2026-09-25。用户要求：
- 长按桌面的 Home 键呼出语音助手，直接对话，始终在同一个对话里。
- 界面是浮在桌面上的磨砂悬浮层，上面有对话气泡；风格类似 Siri 但不照搬，体现苹果式的简约。
- 交互：长按时进入对话、松手相当于说完；界面上还有“按住说话”“停止”等按钮。要求分析这样设计好不好。
- 性能：语音是系统的核心功能，除实时语音连接外，其他资源都应该常驻、预热好。

## 调研

- **Plasma Mobile**（vendor 6.6.5；上游 master `3989db89`，2026-09-25）：
  - 导航栏按钮是 `NavigationPanelButton`（`AbstractButton`），`NavigationPanelAction` 只有 `triggered`，没有长按。
  - 上游 master 也没有长按；以“long press”“press and hold”“assistant”检索上游合并请求，本轮未找到相关工作。
  - 任务栏容器的 C++ 通过 D-Bus 触发外部功能，例如任务切换器走 kglobalaccel 的 `invokeShortcut`。
  - 全局快捷键只有“按下”，没有“松开”；按住说话需要两者，所以改用明确的 D-Bus 接口。
- **交互参考**（只参考设计，不涉及代码）：
  - iPhone 按住侧边键：按住期间 Siri 一直听，松手就结束；短按则由 Siri 自己判断说完。
  - Android 长按 Home（assist）：长按只负责唤起，何时说完由系统判断。
  - 长按时长取 Android 的默认值 400 ms。
- **现状耗时**（本机实测，旧流程）：

  | 环节 | 耗时 |
  |---|---|
  | 语音助手应用启动到窗口出现 | 0.65–0.70 s |
  | 语音服务冷启动（D-Bus 按需激活） | 0.58 s |
  | 打开对话 | 0.14 s |
  | 实时语音连接就绪 | 1.3–1.6 s |
  | 麦克风首帧 | 冷 0.24 s，热 0.055 s |

  此外还要在对话列表里选一个对话。
- **磨砂**：
  - Plasma Mobile 默认不加载 KWin 的 blur（65 篇）。
  - 实测在电视投屏和助理屏都运行时，GPU 平均占用约 50%；加载 blur 后约 57%，说明已有表面在请求模糊。
  - 因此不全局开启，只在悬浮层显示期间加载 blur 和 contrast，隐藏时卸载；如果用户自己已经加载，就不去动它。

## 交互设计（分析结论）

“长按进入对话、松手即说完”作为主路径是对的：
- 和对讲机、Siri 的按住侧边键一样，符合直觉。
- 说完的时刻由手指决定，不依赖服务端 500 ms 的静音判定，和 59 篇的按住说话一致，不会把一句话切成两段。

需要补上的情况：

1. **长按后没说话就松手**（不知道要一直按着，或者想先想一想）。如果把松手当成“说完”，会发出一个空轮次。
   - 做法：松手时如果还没听到说话，转为免提，继续听。
   - 说完（说话之后静音 900 ms）自动发送；8 秒内没听到说话就自动取消，什么都不发送。
   - 这和 Siri 短按时的行为一致。
2. **后续轮次**：悬浮层中间的光球同样是“按住说话”，语义与 Home 键相同，轻点则进入免提。免提中再轻点一次，立即发送。
3. **停止**：Agent 在工作或助手在回答时，右侧按钮变为“停止”；按住光球说话也会打断正在播放的回答。
4. **收起**：
   - 点卡片外、向下滑卡片、或单击 Home（同时回到主屏）都会收起悬浮层。
   - 如果正在听，丢弃这句话；如果在回答，停止播放。
   - Agent 的工作继续进行，完成后悬浮层自动重新弹出显示结果（不开麦克风）；空闲 8 秒后自动收起。
5. **导航栏不被遮挡**：悬浮层的触摸区域不包括导航栏，所以手指在 Home 上按住的整个过程中，事件都留在导航栏里。
6. **按住的上限**（2026-09-28）：一次按住超过 60 秒，就当作松开事件已经丢失，关闭悬浮层并取消录音，已说的内容不发送。起因是一次按住之后一直没收到松开，麦克风和悬浮层的动画就一直开着（49 篇“大核调度与空闲开销”）。同时修复了宿主在暂停渲染时不给客户端发触摸取消的问题。

## 实现

链路：Home 长按（400 ms）→ 任务栏 `assistantHold(true, 屏幕名)` → D-Bus `dev.moto.VoiceAssistant /Assistant Hold` → 常驻悬浮层 → 语音服务 `AssistantTalk(屏幕)` / `ReleaseTalking()`。

| 部分 | 位置 | 内容 |
|---|---|---|
| 导航栏 | `vendor/plasma-mobile`：`NavigationPanelAction`/`Button`/`NavigationPanel.qml`、`containments/taskpanel` | 按钮新增 `holdable`，长按期间不再触发单击；中间按钮（Home）长按发 `Hold(true/false, 屏幕)`，单击回主屏并发 `Hide`。部署：`tools/build_on_device.py plasma-mobile targets` 构建 `mobileshellplugin` 和 `org.kde.plasma.mobile.taskpanel`，再用 `plasma/install-mobile-plugins.sh` 安装，重启 plasmashell |
| 悬浮层 | `plasma/voice-agent/app`：`overlay.cpp`、`qml/AssistantOverlay.qml`、`Orb.qml`、`OverlayItem.qml` | `moto-voice-assistant --overlay`，由用户单元 `moto-voice-overlay.service` 常驻，D-Bus 可按需激活作为兜底。LayerShellQt 覆盖层，出现在按下 Home 的那块屏幕上；导航栏高度取自 `PanelSettingsDBusClient`；卡片形状同时作为 KWin 的 blur/contrast 区域 |
| 对话逻辑 | `qml/ChatModel.qml` | 从聊天页抽出的事件处理，聊天页与悬浮层共用 |
| 语音服务 | `moto_voice_agent.py` | 新增 `OpenAssistant`、`AssistantTalk`、`ReleaseTalking`、`StartListening`、`CancelTalking`；`Endpointer` 做免提的说完判定；向界面发电平事件；随会话启动时预热 |

- **固定的对话**：
  - 助理对话的 id 保存在 `~/.local/share/moto-voice-agent/assistant.json`，在对话列表中显示为“语音助手”，也可以在应用里打开。
  - Codex 要在第一轮对话之后才会保存一个 thread；从没说过话的 thread 在重启后无法恢复，这时新建一个，并删掉那个空条目。
  - 已经有过对话的助理对话，在服务重启后恢复成功（实测）。
  - 应用离开这个对话的页面时，不会关闭它；应用打开别的对话再关掉后，服务会回到助理对话并保持预热。
- **预热**：
  - 语音服务和悬浮层都随会话启动。
  - 服务启动时恢复助理对话，但不连接实时语音；麦克风管线提前建好并停在 READY。
  - 按下时只需开麦克风，并在后台建立实时连接。连接期间的录音在本地排队，就绪后按顺序送出。所以用户按下后就能开口，约 1.4 s 的连接时间和说话时间重叠。
  - 实时连接用完后保持 10 分钟再关闭（原有的 `IDLE_STOP_S`），期间的后续轮次不需要重新连接。
- **视觉**：见下一节“沉浸式重新设计”（2026-09-25 替换了最初的底部卡片和锥形渐变光球）。

## 沉浸式重新设计（2026-09-25）

用户要求：浮层不够沉浸，要重新设计，光效参考 iOS 27 的 Siri。设计稿在 Claude Design 画布“语音助手浮层”（5 张手机稿加光效分解图）。

- **原来的问题**：
  - 底部卡片加很淡的暗幕（0.12–0.25），看起来像弹窗。
  - 光球用的是高饱和的系统色，像彩色按钮；辉光靠 `MultiEffect`（`blurMax` 20），只能晕开很窄一圈，实机上是一块方形雾。
  - 转写挤在气泡里；浅色主题下是白卡片。
- **参考**：iOS 27 的 Siri（9to5Mac、MacRumors 对 beta 的报道，未在设备上核实）：
  - 从灵动岛展开的旋转发光体取代了屏幕边缘的彩虹光；
  - 只有深色界面；
  - 以金色和蓝色为主，发白的亮光，暗底色，少量粉、紫、橙；
  - 发光的光标和状态字，结果在半透明面板里。
  - 本设计只借用这种视觉语言，不照搬它的形状和素材。
- **设计**：
  - 光从手指下的 Home 升起：白热核心、左蓝右粉的漂移色光、暖金到冷蓝的光晕，以及沿底边和两侧向上变淡的细边缘光。全部是柔和衰减，没有描边。
  - 整个屏幕压暗（顶部 0.58 到底部 0.86）并由 KWin 模糊；导航栏上压暗 0.72，按钮仍可见、可点。浮层固定为深色。
  - 三种状态：

    | 状态 | 画面 |
    |---|---|
    | 聆听 | 光完整升起，高度和亮度随音量变化；免提时边缘光减半 |
    | 处理 | 光沉下去，收成 Home 上方的光丸；顶部显示问题，光丸上方是“正在处理 · N 秒”和当前步骤 |
    | 回答 | 本轮内容放在玻璃面板里：问题作为小字说明，答复用大字；上拉展开完整对话 |

  - 光丸两侧：左边“在应用中查看”；右边在工作或回答时是“停止”，其余时候是“关闭”。按住光丸说话，轻点进入免提。
- **实现**（`plasma/voice-agent/app`）：
  - 光效是三个片元着色器，由 CMake 的 `qt_add_shaders` 预编译：`shaders/bloom.frag`（Home 升起的光）、`pill.frag`（光丸，胶囊 SDF，光晕在元件边界前衰减到 0）、`glowtext.frag`（金蓝流光文字，三圈采样的柔和光晕）。
  - QML 组件为 `Bloom`、`LightPill`、`GlowLabel`，替换 `Orb.qml`。
  - `AssistantOverlay.qml` 按“本轮”决定显示哪种状态：开始聆听时记下条目数；松手后等待转写，收到答复、`listen-cancelled` 或 8 秒后结束等待。
  - KWin 的模糊区域从卡片改为导航栏以上的整个区域（`Overlay::setCard`）。仍然只在浮层显示期间加载 blur 和 contrast。
- **性能**（手机 WL-0：1080×2400、3 倍缩放、120 Hz；KGSL `gpu_busy_percentage` 每 0.5 s 采样一次，共 8 s）：

  | 版本 | 聆听时 GPU（开启模糊） | 关闭模糊 |
  |---|---|---|
  | 第一版（按帧驱动，120 Hz） | 90%，816 MHz | 75%，647 MHz |
  | 光按逻辑分辨率画进 layer | 83%，811 MHz | 67%，500 MHz |
  | 去掉 layer，光改由 60 Hz 时钟驱动 | 74%，603 MHz | 70%，320 MHz |

  - 隐藏时为 1–9%，345 MHz。
  - 用 `QSG_RENDER_TIMING` 数帧才发现：layer 每次更新都会再请求一帧，帧数翻倍，这比它省下的片元更费，所以没有用 layer。
  - 电平在 60 Hz 时钟里平滑，不再给每个电平事件起一个动画。
  - 模糊约占一半负载。聆听只持续几秒，暂不继续优化。

## 实机验证（手机 WL-0，浅色主题，电视投屏同时运行）

- **Home 长按**：用 `dbus-monitor` 看到，按下约 400 ms 后发出 `Hold(true, "WL-0")`，松手时发出 `Hold(false)`；长按没有再触发回主屏。
- **端到端**：
  - 在 Home 上按住 5 秒，其间用手机扬声器播放合成语音“帮我看一下磁盘还剩多少空间”，由手机麦克风收音。
  - 悬浮层在收到 `Hold` 后 5 ms 调用 `present`；服务在 `Hold` 后 89 ms 开始录音。当时实时语音未连接（服务刚重启）。
  - 松手后，语音转写正确，Agent 开始执行，8 秒时播报进度；卡片上依次出现用户气泡、“正在处理 · N 秒”、答复。
  - 执行期间有人在手机上点了“在应用中查看”（不是测试脚本操作的，应是用户），应用打开了这个对话；Agent 完成后，悬浮层自动弹出并显示结果。
- **免提**：按住 1 秒后不说话就松手。日志显示 `released before speech, listening hands-free`，界面提示“正在听 · 说完自动发送，轻点结束”，状态栏出现 Android 的麦克风指示；8 秒后 `nothing said, cancelled`。
- **收起**：悬浮层显示时单击 Home，回到主屏，悬浮层收起，blur/contrast 已卸载（已加载特效中不再有两者）。
- **磨砂**：在主屏上打开悬浮层，卡片外的壁纸清晰、只轻微变暗，卡片背后是模糊的。
- **单实例**：先启动应用，再用 `--conversation <助理对话>` 启动第二个；第二个立即退出（返回码 0），已运行的应用打开了“语音助手”对话，没有关闭重开实时连接。
- **重构回归**：`ChatModel` 抽出后，59 篇的五种事件时序在真实 QML 离屏回放中，结果与重构前完全一致。
